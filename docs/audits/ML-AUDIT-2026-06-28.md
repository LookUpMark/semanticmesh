## 3. Findings

### F-001 — RED — Preset ablation reads `run_query()` with non-existent keys → all metrics silently wrong

| Field | Value |
|---|---|
| **Location** | `src/api/ablation_router.py:438-446` |
| **Category** | interface-contract / model-IO-contract |
| **Title** | `_run_ablation_task_with_preset` reads `run_query()` result with non-existent keys → all metrics silently wrong |
| **Description** | The preset path (launched by `POST /ablation/run/preset`) reads `query_state.get('answer')`, `.get('contexts')`, `.get('rerank_scores')`, `.get('is_grounded')`. **None of these keys exist** in the `run_query()` return contract (`query_graph.py:625-643`), which returns `final_answer`, `retrieved_contexts`, `retrieval_quality_score`, `retrieval_chunk_count`, `grader_grounded`. Every `.get()` falls back to its default. The sibling custom path `_run_ablation_task` (lines 227-233) reads the **correct** keys — this is a copy-paste regression, not an intentional shape change. |
| **Evidence** | `ablation_router.py:439` `answer = query_state.get("answer", "")` → always `""`; `:442-444` `rerank_scores` always `None` → `score = 0.0`; `:446` `is_grounded` always `True`. Verified: `grep` confirms `rerank_scores`/`is_grounded` appear **only** in the preset path. |
| **Impact** | The entire **primary advertised ablation endpoint** produces invalid, silently wrong results: every answer `''`, every `top_rerank_score` `0.0`, every `chunk_count` `0`, every `is_grounded` `True`. Derived metrics are meaningless and flow into `run.json`, the evaluation bundle, and `GET /ablation/status`, invalidating any ablation study launched via preset and the downstream AI-as-Judge. |
| **Remediation** | Mirror the correct sibling path: `answer = query_state.get('final_answer','')`, `contexts = query_state.get('retrieved_contexts') or []`, `score = query_state.get('retrieval_quality_score',0.0)`, `chunk_count = query_state.get('retrieval_chunk_count',0)`, `is_grounded = bool(query_state.get('grader_grounded',True))`. **Best:** extract a shared `_score_query_result(qr)` helper used by both paths so they cannot diverge again. |
| **Effort** | S |
| **Status** | FIXED |

### F-004 — ORANGE — `MENTIONS` edges link BusinessConcepts to wrong Chunk nodes

| Field | Value |
|---|---|
| **Location** | `src/graph/build_nodes.py:476-505` (also `builder_graph.py:756`) |
| **Category** | cross-module-contract-break / KG-provenance-corruption |
| **Description** | Triplets are extracted from **parent** chunks (`source_chunk_index` is a parent index), but the `MENTIONS`-edge Cypher `MATCH (ch:Chunk {chunk_index: idx})` matches **child** `:Chunk` nodes (parents are `:ParentChunk` keyed on `parent_chunk_index`). The two label spaces are disjoint and both indices start at 0. So a triplet's parent index is matched against whatever child chunk happens to carry the same number — a different piece of text, or nothing. |
| **Evidence** | Both `MENTIONS` paths match parent index against child `:Chunk`. Verified via `grep`. |
| **Impact** | Silent KG provenance corruption: concepts get `MENTIONS` edges to semantically-unrelated child chunks (or lose grounding). **Downgraded from RED→ORANGE:** `MENTIONS` is **never traversed** in retrieval (hybrid_retriever uses `CHILD_OF`, not `MENTIONS`), so answer correctness is unaffected, but chunk→concept grounding metadata is wrong and orphan-concept cleanup (`file_registry.py:207`) may make wrong decisions. |
| **Remediation** | Point the `MENTIONS` MATCH at the parent space: `MATCH (ch:ParentChunk {parent_chunk_index: idx})`. |
| **Effort** | S |
| **Status** | FIXED |

| **Effort** | M |
| **Status** | FIXED |

### F-018 — GREEN — Heuristic extraction slices original sentence with indices from lowercased copy

| Field | Value |
|---|---|
| **Location** | `src/extraction/heuristic_extractor.py:82-92` |
| **Category** | preprocessing-bug / unicode-misalignment |
| **Description** | The mapping-pattern regex is searched against `lowered=sentence.lower()`, but match spans are applied to the **original** sentence. `str.lower()` can change length for U+0130 `İ` (lowercases to 2 code points), shifting every subsequent offset by +1 and extracting garbled substrings. |

| **Remediation** | Compile `_MAPPING_PATTERNS` with `re.IGNORECASE` and `pattern.search(sentence)` directly (drop the `lowered` line). Eliminates the whole length-delta class for free. |
